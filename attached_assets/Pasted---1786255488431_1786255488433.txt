Твоя задача — выполнить Кейс-задачу №4 для студента направления 09.03.02 «Информационные системы и технологии».

## Входные данные (задание)

Необходимо разработать мобильное приложение для ведения заметок в организации. 
Функции:
1. Создание заметки (заголовок, дата, время, содержание).
2. Редактирование заметки.
3. Удаление заметки.
4. Поиск заметки (по ключевым словам, дате, времени).

Хранение данных (два способа):
- SQLite (локальная БД).
- Файловая система (сохранение заметок в виде отдельных файлов, например, .txt или .json).

Дополнительно:
- Интуитивный UI.
- Желательна кросс-платформенность (iOS/Android).
- Синхронизация через облачные сервисы — как опциональный бонус.

Итоговые deliverables (что нужно сдать):
1. Руководство пользователя с иллюстрациями (описание экранов, кнопок, сценариев работы).
2. Описание функциональных возможностей приложения (архитектура, технологии, как реализованы два способа хранения).
3. Ссылка на приложение (или на исходный код, или на APK/демо).
4. Пояснение для научного руководителя практики: как протестировать приложение (какие тест-кейсы выполнить, какие данные ввести, чтобы проверить все функции).

## Что нужно сделать

Предложи полное решение этой задачи в виде готового отчета. Требования к ответу:

### Часть 1. Архитектура и технологии
- Выбери стек технологий React Native .
- Опиши структуру проекта (MVVM, BLoC или другой паттерн).
- Детально опиши, как организовано хранение:
  - Схема таблицы SQLite.
  - Формат файлов на файловой системе (например, JSON-файлы с полями id, title, date, time, content).
- Опиши, как переключается режим хранения (переключатель в настройках или выбор при создании заметки).

### Часть 2. Реализация (код)
Предоставь рабочий код приложения (для выбранного фреймворка). Код должен быть:
- Полностью рабочим (можно скопировать и запустить).
- С комментариями на русском (или английском) по ключевым блокам.
- Обязательно реализовать:
  - Экран списка заметок с поисковой строкой.
  - Экран создания/редактирования заметки.
  - Диалог подтверждения удаления.
  - Настройки для выбора типа хранилища (SQLite / Файлы).

Для упрощения допускается использовать эмуляцию или локальный сервер для облачной синхронизации (если реализуешь).

### Часть 3. Руководство пользователя
Создай пошаговое руководство с иллюстрациями (в текстовом виде опиши каждый экран, его элементы, а также приложи ASCII-схемы или детальные текстовые описания интерфейса, которые можно легко превратить в скриншоты). Включи:
- Как создать заметку.
- Как редактировать (например, тап по заметке).
- Как удалить (свайп или кнопка).
- Как искать (поисковая строка, фильтры по дате).
- Как переключить способ хранения.

### Часть 4. Инструкция по тестированию для научного руководителя
Напиши отдельный раздел «Как проверить приложение». Включи:
- Чек-лист тест-кейсов (по каждому CRUD-действию для каждого типа хранилища).
- Какие данные вводить для проверки поиска.
- Как проверить, что данные действительно сохранились в SQLite (например, через ADB или встроенный просмотрщик БД).
- Как проверить файловое хранение (найти созданные файлы в папке приложения).
- Сценарий проверки переключения между хранилищами (создать заметку в SQLite, переключить на файлы — проверить, что заметки не потерялись или что интерфейс корректно показывает только заметки из активного хранилища).

### Часть 5. Ссылка на приложение
Предложи удобный способ предоставить приложение для проверки:
- Если это Flutter — дай команды для сборки APK и ссылку на GitHub-репозиторий с кодом.
- Либо предложи готовый APK-файл, выложенный на облако (Google Drive / Яндекс.Диск) с инструкцией по установке.
- Включи также инструкцию по запуску в эмуляторе (Android Studio / Xcode) для тех, кто будет проверять исходники.

### Часть 6. Бонус (опционально)
Если реализуешь облачную синхронизацию — опиши, как она работает (Firebase / собственный бэкенд) и как её тестировать.
